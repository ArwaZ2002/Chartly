للمؤسسة1. نظرة عامة على المشروعChartly هي أداة داخلية موجهة لمحللي البيانات ضمن المؤسسة، تتيح لهم رفع ملفات البيانات واستخدام واجهة تحليل موجهة (Guided Analysis Builder) لاختيار نوع المخطط، والأعمدة المراد تحليلها، وطريقة التجميع وبعض خيارات العرض. يقوم النظام بتحليل بنية البيانات تلقائيًا، والتحقق من توافق الاختيارات مع أنواع الأعمدة، ثم توليد الجداول والمخططات البيانية باستخدام محرك رسم برمجي.في الإصدار الحالي لا تعتمد Chartly على نموذج لغوي كبير (LLM) أو مزود ذكاء اصطناعي خارجي. بدلاً من ذلك، يعتمد النظام على Data Profiling وقواعد التحقق والتوصية (Rule-Based Logic) لبناء مواصفات المخطط (Chart Specification) ثم تحويلها إلى مخطط قابل للتفاعل.يستطيع المحلل تعديل إعدادات التحليل وإعادة توليد المخطط مع الاحتفاظ بسجل للمحاولات. ويمكن حفظ المخطط النهائي كقالب (Template) قابل لإعادة الاستخدام والتخصيص ضمن مكتبة مشتركة على مستوى الفريق.الهدف الأساسي هو اختصار الوقت بين امتلاك الداتا الخام والوصول إلى مخططات جاهزة وقابلة لإعادة الاستخدام، مع تقليل الإعداد اليدوي المتكرر والحفاظ على اتساق المخرجات.2. أهداف المشروع• تسريع إنشاء الجداول والمخططات البيانية عبر واجهة تحليل موجهة.• تقليل الاعتماد على أدوات خارجية متفرقة لإنشاء المخططات.• توفير Data Profiling تلقائي لاكتشاف أسماء الأعمدة وأنواعها وبعض خصائص البيانات.• تقديم خيارات تحليل ديناميكية تتوافق مع نوع المخطط ونوع الأعمدة المختارة.• تقديم توصيات أولية لنوع المخطط المناسب بناءً على خصائص البيانات.• بناء مكتبة Templates مشتركة وقابلة لإعادة الاستخدام على مستوى الفريق.• ضمان الاتساق البصري عبر خيارات موحدة للعناوين والألوان وإعدادات العرض.• توفير Audit Trail لعمليات إنشاء وتعديل وإعادة توليد المخططات.• إدارة الوصول للمنصة عبر أدوار وصلاحيات واضحة (Viewer / Analyst / Admin).3. نطاق العملضمن النطاق — المرحلة الأولى وما بعدها• رفع ملفات CSV وExcel.• Data Profiling واكتشاف أنواع الأعمدة الأساسية.• معاينة عينة من البيانات.• واجهة Guided Analysis Builder لاختيار نوع المخطط والأعمدة المراد تحليلها.• دعم Bar وLine وPie وScatter في المرحلة الأولى.• اختيار Dimensions وMetrics وAggregation عند الحاجة.• قواعد تحقق تمنع التركيبات غير المتوافقة.• Chart Recommendations اختيارية مبنية على قواعد البيانات.• توليد المخطط عبر محرك رسم برمجي مثل Plotly أو مكتبة مكافئة.• إعادة توليد المخطط مع الاحتفاظ بالإصدارات السابقة.• تصدير المخطط النهائي كصورة JPG/PNG.• حفظ المخطط كقالب كود في مكتبة مشتركة.• تخصيص العنوان والألوان وبعض إعدادات العرض.• إدارة Viewer / Analyst / Admin.خارج النطاق — المرحلة الأولى• استخدام LLM أو أي API خارجي لفهم تعليمات نصية حرة أو توليد المخططات.• إرسال بيانات المؤسسة إلى مزود ذكاء اصطناعي خارجي.• ربط APIs أو قواعد البيانات؛ يؤجل لمرحلة لاحقة.• Dashboards وHeatmaps والمخططات المتقدمة؛ تؤجل لمرحلة لاحقة.• التصدير إلى PDF أو PPTX أو Excel؛ التصدير الحالي صور فقط.• مشاركة القوالب خارج الشركة أو إنشاء متجر عام.• الاشتراكات والفوترة؛ المنصة أداة داخلية التفصيلية6.1 إدارة البيانات (Data Management)• FR-1.1 رفع CSV أو Excel كمصدر تحليل.• FR-1.2 معاينة عينة من البيانات بعد الاستيراد.• FR-1.3 اكتشاف أنواع الأعمدة تلقائيًا.• FR-1.4 عرض ملخص أساسي للأعمدة مثل النوع والقيم الفريدة والقيم المفقودة عند توفرها.6.2 Guided Analysis Builder• FR-2.1 اختيار نوع المخطط من قائمة الأنواع المدعومة.• FR-2.2 اختيار الأعمدة من قوائم ديناميكية تعتمد على نوع البيانات.• FR-2.3 اختيار Dimension/Category وMetric/Value حسب نوع المخطط.• FR-2.4 اختيار Sum وAverage وCount وMin وMax عندما تكون مناسبة.• FR-2.5 اختيار Sorting وTime Granularity وبعض إعدادات العرض.• FR-2.6 منع الخيارات غير المتوافقة مع أنواع الأعمدة.• FR-2.7 اقتراح مخطط مناسب اختياريًا بناءً على خصائص البيانات.• FR-2.8 عرض ملخص لإعدادات التحليل قبل التوليد.6.3 توليد وإدارة المخططات• FR-3.1 توليد المخطط من Chart Specification منظمة ناتجة عن اختيارات المستخدم.• FR-3.2 عرض المخطط بشكل تفاعلي داخل المنصة.• FR-3.3 تعديل الإعدادات وإعادة التوليد.• FR-3.4 حفظ كل نسخة مع إعداداتها والطابع الزمني.• FR-3.5 تصدير المخطط النهائي JPG/PNG.6.4 مكتبة القوالب• FR-4.1 حفظ المخطط كقالب قابل لإعادة الاستخدام.• FR-4.2 إتاحة القوالب لبقية أعضاء الفريق حسب الصلاحيات.• FR-4.3 تعديل العنوان والألوان وإعدادات العرض الأساسية.• FR-4.4 البحث بالاسم أو نوع المخطط.• FR-4.5 إعادة استخدام قالب على Dataset جديد مع التحقق من توافق الأعمدة.6.5 إدارة المستخدمين والصلاحيات• FR-5.1 إضافة وإزالة المستخدمين وتحديد أدوارهم.• FR-5.2 Viewer يستطيع الاستعراض فقط.• FR-5.3 Admin يدير إعدادات المنصة والصلاحيات.6.6 سجل التدقيق (Audit Trail)• FR-6.1 تسجيل إنشاء وإعادة توليد كل مخطط مع المستخدم والتاريخ والوقت.• FR-6.2 حفظ Chart Specification والإعدادات لكل نسخة.• FR-6.3 إتاحة الرجوع إلى النسخ السابقة وفق الصلاحيات.7. المتطلبات غير الوظيفية• الأمان: تشفير البيانات أثناء النقل والتخزين عند الحاجة وتطبيق صلاحيات الوصول.• التحكم بالوصول: تطبيق صلاحيات Viewer/Analyst/Admin على مستوى كل شاشة وإجراء.• Audit Trail: تسجيل عمليات التوليد وإعادة التوليد مع المستخدم والوقت والإعدادات.• الأداء: تحديد حدود حجم البيانات وزمن التوليد عبر PoC.• قابلية التوسع: البدء بفريق تحليل بيانات واحد.• التوافق: Firefox وEdge وChrome الحديثة.• الاعتمادية: الوظائف الأساسية للـMVP لا تعتمد على مزود AI خارجي.8. المخاطر والقرارات المفتوحة• أحجام البيانات وعدد المستخدمين المتزامنين غير محددة: إجراء PoC ببيانات واقعية.• قد يخطئ Data Profiling في ملفات غير نظيفة: السماح للمستخدم بتعديل نوع العمود يدويًا.• قد تحتاج بعض المخططات إلى قواعد تحليل معقدة: بناء Rule Engine قابل للتوسع.• قد لا تتوافق القوالب مع أسماء أعمدة Dataset جديد: إضافة Template Mapping/Validation.• المخططات المتقدمة قد تحتاج مكتبات مختلفة: تحديدها في المرحلة الثانية.9. المراحل المقترحة للتنفيذالمرحلة الأولى — MVP• رفع CSV/Excel.• Data Profiling واكتشاف أنواع الأعمدة.• معاينة البيانات.• Guided Analysis Builder.• Bar / Line / Pie / Scatter.• اختيار الأعمدة وAggregation وSorting وTime Granularity.• Validation Rules.• Chart Recommendations مبنية على القواعد.• توليد وعرض المخطط تفاعليًا.• Regenerate مع Version History وAudit Trail.• تصدير JPG/PNG.• حفظ ومشاركة Templates.• Viewer / Analyst / Admin.المرحلة الثانية• ربط APIs وقواعد البيانات.• Dashboards وHeatmaps ومخططات متقدمة.• تخصيص أوسع للقوالب.• تحسين Template Mapping.• إحصاءات وتحليلات متقدمة حسب احتياجات الفريق.المرحلة الثالثة• تحسين الأداء والتوسع.• توسيع Rule-Based Recommendation Engine.• دراسة إضافة Natural Language Guidance أو LLM كميزة اختيارية مستقبلية فقط إذا ثبتت الحاجة ومتطلبات الخصوصية تسمح بذلك.11. معايير النجاح العامة• انخفاض الوقت من الداتا الخام إلى مخطط جاهز من ساعات إلى دقائق.• ارتفاع استخدام مكتبة القوالب المشتركة.• انخفاض الاعتماد على أدوات خارجية.• ارتفاع نسبة نجاح إنشاء مخطط صحيح من المحاولة الأولى.• انخفاض أخطاء اختيار الأعمدة وأنواع المخططات بفضل Data Profiling وValidation.• رضا المحللين عن سهولة Guided Analysis Builder ودقة التوصيات القائمة على القواعد.
